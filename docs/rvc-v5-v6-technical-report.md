# Haruka RVC v5–v6 系列技术报告

- **报告类型：** 基于项目记录的模型技术报告
- **记录截止日期：** 2026-09-20
- **覆盖版本：** v5 e40/e60/e80、v6a e200、v6b e500；v6c 仅说明其试验状态

## 摘要

本文整理 Haruka 歌唱音色转换模型 v5 至 v6 系列的训练配置、数据准备、模型改动、推理流程和现有验收证据。该系统属于基于检索的歌唱语音转换（singing voice conversion），目标是在保留输入演唱的时间、旋律和发音走势的条件下，将音色转换为 Haruka；它不是文本生成语音系统，也不是通用大语言模型。

v5 是基于 RVC v2、40 kHz、启用 F0 的基线训练。e40、e60、e80 是同一次 100 轮训练中的检查点，并非三次独立训练。v6a 保留基线网络拓扑和推理路径，增加多分辨率频谱、高频与静音尾部损失；同一续训序列中的 e200 被选为稳定版本，并在一首完整歌曲上获得用户对干声和混音的试听确认。v6b 在 v6a 损失配置上加入逐帧 F0、清浊音和能量条件分支，训练至 e500。v6b 的权重、索引和整曲输出已通过技术合同检查，但听感仍待验收。

现有记录支持对模型结构和训练过程作有限、可追溯的说明；尚不足以支持 v6b 优于 v6a、跨歌曲泛化率或公开基准分数等结论。文中将技术通过、具体歌曲上的人工试听通过和待验收状态分开报告。

**关键词：** 歌唱语音转换；RVC；HuBERT；RMVPE；FAISS；Haruka

## 1. 任务定义与报告范围

输入为经人声分离得到的歌唱人声，输出为目标音色的歌唱人声；如果生成完整翻唱，再将转换人声与匹配伴奏混音。模型不根据歌词生成旋律或演唱，也不替代人声分离、对齐或伴奏制作。

本文以截至 2026-09-20 的本地模型清单、训练报告、准备报告、代码和验收记录为证据。版本边界如下：

| 系列版本 | 本文采用的版本身份 | 当前证据状态 |
| --- | --- | --- |
| v5 | 一次 100 轮训练中的 e40、e60、e80 检查点 | 训练和推理技术记录存在；没有在模型清单中登记为稳定版 |
| v6a | e500 续训序列中选出的 e200 / s6000 | 已登记为 stable；用户确认了指定歌曲的干声与整曲试听 |
| v6b | v14-lite-r1 数据与条件分支训练得到的 e500 / s15000 | candidate；训练、索引和若干转换技术通过，主观验收待完成 |
| v6c | 基于 v6b 的 learned Router pilot | 当前工作索引标为 blocked；没有可报告的训练权重或听感结果 |

本文中的“稳定版”仅指当前清单状态和已有验收范围，不代表所有输入歌曲均有相同表现。

## 2. 系统结构

RVC 的常规处理链包含音频预处理、F0 与 HuBERT 特征提取、生成器/判别器训练、特征索引构建和转换推理。RVC 官方流程文档描述了这一训练与离线转换路径；本地项目也使用 40 kHz、v2、F0 和 768 维特征索引。[1]

| 阶段 | 输入 | 主要处理 | 输出 |
| --- | --- | --- | --- |
| 语料准备 | 训练歌唱音频 | 切段、统一为 40 kHz 单声道、提取内容与 F0 特征 | 452 个训练片段及其特征文件 |
| 模型训练 | 音频片段、HuBERT 特征、F0 | 训练 F0 条件生成器和判别器；v6a 起附加损失项 | 推理权重 |
| 检索索引 | 训练集 HuBERT 特征 | 构建 IVF1345 / IndexIVFFlat 特征索引 | 与模型配套的 FAISS index |
| 单曲转换 | 输入干声、配套权重和 index | HuBERT 内容特征、RMVPE F0、检索融合、分段生成与拼接 | 40 kHz 单声道转换人声 |
| 完整翻唱 | 转换人声、匹配伴奏 | 重采样、增益处理和混音 | 44.1 kHz 双声道 WAV |

本地 40 kHz v2 配置记录的主要网络尺寸为：mel 频谱 125 通道、hop length 400、隐藏维度 192、6 层内容编码器、2 个注意力头、filter channels 768，以及核大小 3/7/11 的残差块和 10/10/2/2 上采样倍率。v5 训练命令记录了 v2、40 kHz 与 F0 开启；v5 运行的独立配置文件及其哈希没有一并归档，因此上列具体网络尺寸应理解为当前基线配置和 v6 配置可核对的结构参数，不是 v5 专属配置快照。

HuBERT 用于抽取音频内容表征；该表征的自监督学习方法见原始 HuBERT 论文。[2] RVC v2 使用 768 维特征，本项目的 v5 index 报告也记录了 768 维。RMVPE 用于推理时估计歌唱 F0；其原始论文研究了复音音乐中的人声音高估计。[3]

v5 的准备报告记录了 128 个训练源文件和 452 个片段。[5] v6a 训练准备的归档报告同样记录了 128 个源文件和 452 个片段。v6b 使用 v14-lite-r1 版本的 452 个已接受片段，并生成逐帧条件元数据。[7]

| 数据项 | 记录值 | 说明 |
| --- | ---: | --- |
| 训练源文件 | 128 | 项目内部 Haruka 歌唱语料的训练条目数 |
| 训练片段 | 452 | 预处理后进入训练清单的音频片段数 |
| v6 数据集切分 | train 128、validation 34、benchmark 40 | 切分报告按条目计数；哈希泄漏与歌曲泄漏字段为空 |
| 采样率 / 声道 | 40 kHz / 单声道 | 训练音频准备合同 |
| 训练时长 | 未完整记录 | 当前可用报告没有统一、可复算的总小时数 |

数据集名称中的 v14-lite、v14-lite-r1 表示项目内部数据版本。本文不列出来源歌曲与原始录音清单，也不据此推断这些音频已获得公开再分发授权。

| 选择用于比较或发布的检查点 | e40、e60、e80；同一次训练 | e200 / s6000 | e500 / s15000 |

v5 的训练报告列出 batch size 4、目标 100 轮、segment size 12,800、scalar optimizer，并保存 e20、e40、e60、e80、e100。其常用对照权重 e40/e60/e80 的全局步数分别为 4,560、6,840 和 9,120。它们共享同一训练运行和数据，不应当作独立随机种子实验。[5]

v6a 的稳定检查点 e200 来自续训到 e500 的序列。模型比较记录显示，e200 在当时的同条件轮次预览和频谱/周期性代理比较中被选为首选，e500 保留为备选。模型清单登记了 e200 权重、配套 IVF1345 index、文件哈希和推理参数。[4]

v6b 的正式训练报告记录训练完成、返回码为 0、目标 500 轮、每 50 轮保存，训练耗时约 4,135 秒。有效训练配置为 batch 16、GPU 数据缓存、segment size 12,800、v6a_loss 和 v6b 条件分支开启。基础配置中的 epochs=20,000 是上限配置，实际目标由正式运行状态中的 500 轮记录确定。[6]

## 5. v6 系列改动

### 5.1 v6a：损失项扩展

v6a 的第一阶段保持生成器网络拓扑和推理路径不变，重点扩展训练损失，并记录有声、无声、安静区和高 F0 区的比例。可查配置中的基线 mel 与 KL 系数分别为 45 和 1.0；新增项如下。[8]

$$
L_{\mathrm{v6a}} = L_{\mathrm{RVC}} + 0.10 L_{\mathrm{MRSTFT}} + 0.05 L_{\mathrm{HF}} + 0.05 L_{\mathrm{tail}}
$$

- **多分辨率 STFT 损失：** 对 512、1024、2048 点 STFT 的谱收敛项和对数幅度误差求平均，减少只在单一频率分辨率下约束的情况。
- **高频损失：** 对 6 kHz 及以上频带的对数幅度误差施加约束。它是训练目标的一部分，不能单独证明听感中的金属感已消失。
- **静音/尾部损失：** 按帧比较目标与生成音频 RMS，在目标静音区和最后一个有声帧之后的静音区惩罚残留能量。

以上实现可在外部运行目录的 train/losses.py 与 scripts/cloud_rvc.py 中核对；仓库内模型清单目前将 v6a 的配置哈希标记为 legacy-imported。[8]

### 5.2 v6b：逐帧条件分支

v6b 沿用 v6a_loss，并新增一条三通道条件输入：

| 条件通道 | 构造方式 |
| --- | --- |
| relative_log_f0 | 有声帧取 log(F0)，减去该样本有声帧 log(F0) 中位数；无声帧置零 |
| uv | F0 小于或等于零时标为无声，其余为有声 |
| normalized_log_rms | 以 hop 为单位计算 log RMS，并减去有声帧能量参考中位数 |

代码中的条件编码器由 1D 卷积、SiLU 和 1D 卷积组成；其输出通过零初始化门控加到生成器输入。这样训练从一个门控初值为零的条件支路开始，之后由训练更新门控和编码器。运行时会检查条件帧数、UV/F0 一致性、有限值和帧轴对齐。[8]

这项变化使 v6b 同时改变了生成器结构、条件输入和数据元数据。当前的 v6a 与 v6b 结果还不是只改变一个变量的完整消融实验，因此不据此归因“条件分支单独带来某种听感提升”。

### 5.3 v6c：试验分支边界

项目外部目录中有基于 v6b 的三专家 learned Router 代码和标签准备记录；当前仓库工作索引将 v6c pilot 标为 blocked，且没有可引用的正式训练权重、推理试听和质量验收。因此本文不把 v6c 当作已发布型号，不纳入 v5/v6a/v6b 的结果比较。[4]

## 6. 推理与混音设置

| 设置 | v5 常见对照 | v6a / v6b 当前登记参数 |
| --- | --- | --- |
| F0 提取 | RMVPE | RMVPE |
| pitch shift | 0 | 0 |
| index rate | 多数整曲对照为 0.25；云端 e100 基线评测为 0 | 0.1 |
| RMS mix rate | 多数整曲对照为 0.17 | 1.0 |
| protect | 多数整曲对照为 0.16 | 0.33 |
| 分块 | 7 秒核心区、0.5 秒上下文 | 7 秒核心区、0.5 秒上下文 |
| 块间拼接 | 按任务记录执行；不是 v5 训练配置 | 100 ms overlap-add |
| 混音输出 | 多个任务使用 44.1 kHz 双声道 | 44.1 kHz 双声道 |

v5 的运行推理参数存在任务差异，不能将某一首歌曲的 index/RMS/protect 参数当作所有 v5 输出的固定配置。v6a/v6b 清单使用同一组登记参数。长音频采用分块主要是为了避免整曲单块推理的显存问题，并保证核心区连续覆盖；音频文件完整性检查与人工听感检查仍是两道不同门槛。[4, 5, 6]

## 7. 现有验证结果

| 版本 / 样本 | 技术证据 | 人工质量状态 |
| --- | --- | --- |
| v5 e100 评测 | 报告验证 6 个输出文件：一个源样本、两个 validation 片段、三个 benchmark 片段；输出为 40 kHz 单声道 WAV [5] | 不能从文件合同通过推导为模型整体接受；系列记录仍为 quality_pending |
| v6a e200 / GUMI 整曲 | 241.241 秒输入完成 35/35 段，核心区无尾帧补零；混音为 44.1 kHz、双声道、10,638,739 帧，技术合同通过 [4] | 用户确认转换干声和人声加伴奏整曲试听通过；e200 已登记 stable |
| v6b e500 / 《白線》 | 32/32 段完成；最终 44.1 kHz 双声道混音为 9,692,004 帧，技术合同通过 [4, 6] | 主观听感待验收 |
| v6b e500 / Wishing Umbrella | 211.733 秒输入完成 31/31 段；经 100 ms overlap-add 重建，独立验证器通过 [4] | 主观听感待验收 |

v6b 固定样本对照、索引构建和《白線》输出有外部归档记录；《Wishing Umbrella》本地候选也有独立报告。当前结论是 v6b 已达到技术通过，尚未达到用户试听接受门槛。v6a 的用户确认对应指定输入和整曲混音，不等价于对所有歌曲作通用质量担保。[4, 6]

现有材料没有 MOS、盲听偏好率、跨说话人测试或多随机种子统计。因而本报告不提供“质量提升百分比”或跨歌曲排名。

## 8. 版本差异的解释

1. **v5 → v6a：** 可确认的主要变化是训练目标增加多分辨率频谱、高频和静音尾部约束；v6a 第一阶段没有改变网络拓扑与推理路径。v6a 还使用更大的 batch 和 GPU 缓存训练设置。
2. **v6a → v6b：** v6b 继续使用 v6a_loss，同时加入基于 F0/UV/RMS 的逐帧条件分支和 v14-lite-r1 元数据。由于条件结构和训练数据版本一并变化，不能把两版差异解释为单一条件支路的因果效果。
3. **检查点含义：** v5 e40/e60/e80 是同一训练序列；v6a e200 是 e500 续训序列中的选定检查点；v6b e500 是新候选。epoch 数不能跨不同训练配置直接等同为质量等级。
4. **状态含义：** v6a e200 是当前已接受的稳定默认；v6b e500 是最新已训练且技术通过的候选；两者的质量状态不能混写。

## 9. 复现性与披露限制

- **v5：** 训练命令、样本数、轮数和 index 报告存在，但该次运行的独立 config.json 和配置哈希没有随归档保存；当前基线配置不能替代原运行配置快照。
- **v6a：** 模型清单的 config_sha256 为 legacy-imported，说明没有可用于逐字节复核的配置哈希。
- **v6b 随机种子：** v6b 模型清单 seed 字段为 20260919；正式训练日志打印的 train.seed 为 1234。当前归档没有解释二者分别代表什么，因此公开复现前应确认训练实际使用的随机种子。[4, 6]
- **数据规模：** 可复核训练源条目数与片段数；完整小时数、录音条件分布和全部授权信息未包含在现有报告中。
- **模型发布范围：** 权重、FAISS index、训练音频和生成音频位于外部资产目录；Git 仓库保存代码与模型清单。现有材料没有证明这些资产已经公开授权再分发，本文不宣称权重或数据集已作为开放模型发布。
- **评测范围：** 目前没有对 v5、v6a、v6b 在同一组源音频、同一伴奏、同一推理参数下完成并由多名听者评分的盲测。

## 10. 结论

Haruka RVC v5–v6 的技术演进可概括为：v5 建立 RVC v2 40 kHz F0 基线；v6a 在保持基线拓扑和推理路径的前提下扩展训练损失，并以 e200 作为目前通过指定歌曲人工验收的稳定检查点；v6b 将 F0、清浊音和能量作为逐帧条件输入，完成 e500 训练和技术验证，但尚待人工试听。

因此，当前最稳妥的对外技术陈述是：**v6a e200 是已接受的稳定版本；v6b e500 是最新的技术通过候选。现有证据不足以宣称 v6b 在总体听感上优于 v6a。** 对外发布前还应补齐 v5/v6a 的精确配置快照、v6b 种子解释、数据授权说明以及同条件盲听评测。
